# Web3 求职入门资料包（适合大陆求职者）

## 这份资料包是做什么的

这份资料包基于以下几类资料整理：

- Web3 共学与公开学习记录
- Web3 求职与社区平台
- 大陆环境下更稳妥的学习与求职边界

目标不是教你“炒币”，而是帮助你用更安全、更可执行的方式进入 Web3 技术岗位视角：

- 先建立基础认知
- 再完成最小上手实践
- 再做项目和公开记录
- 最后再进入求职准备

## 一句话判断

如果你人在大陆，适合做的是：

- Web3 技术学习
- 智能合约开发
- 安全研究
- 链上数据分析
- 开源贡献
- 面向海外团队的远程岗位准备

不适合碰的是：

- 币价喊单
- 交易所导流
- 发币营销
- 面向境内用户的虚拟货币交易推广

所以，正确姿势不是“做币圈内容”，而是把 Web3 当成一个全球化的技术方向来进入。

## 适合哪些人

这条路线更适合以下几类人：

- 已有前端、后端、测试、安全基础，想往 Web3 技术栈转
- 想找远程岗位，愿意读英文文档、做公开作品集
- 能接受行业波动，不把 Web3 当成短期暴利机会

如果你是完全零基础，建议先补下面这些通用基础：

- Git 和 GitHub
- JavaScript 或 TypeScript
- 基本命令行能力
- 基础英文阅读能力

## 更贴合你当前背景的判断

从你当前工作区里的内容看，你更接近这类画像：

- 正在走后端工程师求职路线
- 在系统补操作系统、网络、系统设计、工程基础
- 对技术写作和知识整理有持续输出
- 当前更像是 Web2 后端能力较强，Web3 经验较少

这意味着你转 Web3 的优势很明确：

- 后端基础可以直接迁移到链上数据、索引服务、基础设施方向
- 系统设计能力对做节点服务、事件消费、数据同步很有价值
- 技术写作能力有利于做公开学习记录和项目展示
- 求职表达能力比纯新手更容易建立可信度

你当前最需要补的，不是重新学一遍计算机基础，而是补这些差异化能力：

- 钱包、签名、交易、合约调用这些 Web3 基本心智
- Solidity 和智能合约安全基础
- 前端与钱包连接的最小 dApp 交互能力
- 链上数据读取、解析、索引的工程实践
- Web3 语境下的 GitHub 项目展示方式

一句话说，你不是从零开始转 Web3，而是从“后端工程师”转成“懂链上系统的后端工程师”。

## 入门总路线

推荐按照下面这个顺序学习：

1. 先理解 Web3 基础概念
2. 学会钱包和测试网的基本操作
3. 补齐安全常识
4. 建立比特币和以太坊的协议层认知
5. 开始 Solidity 和 dApp 开发
6. 做公开项目和学习记录
7. 再进入岗位投递和社区曝光

不要一开始就追热点、看币价、刷空投。这些内容对技术求职帮助很小，反而容易把方向带偏。

## 你的转型路线图

如果按你现在的背景来设计，我建议不要把目标定成“纯合约工程师”起步，而是走下面这条更稳的路线：

1. 先补 Web3 最小认知和钱包操作
2. 再补 Solidity 和合约交互，建立链上执行直觉
3. 然后把重点放到链上数据、索引、事件消费、服务端工程
4. 最后再决定是否往合约开发或安全审计方向继续加深

更具体地说，你最适合优先冲这三类岗位：

- Web3 Backend Engineer
- Full-Stack Web3 Engineer（偏后端）
- Blockchain Data / Infra Engineer

如果后面你对安全很感兴趣，再往这些方向延伸：

- Smart Contract Security
- Contract Audit Assistant
- Protocol Research

不建议你一开始就把主线压在这些方向：

- 纯运营型 Web3 内容
- 重交易叙事的自媒体路线
- 高度依赖市场周期的投机岗位

## 适合你的项目路线

相比“做一个简单投票 dApp”，你更适合做带后端含量的项目。

推荐项目顺序：

### 项目 1：最小合约项目

做什么：

- 写一个 Counter、Todo 或投票合约
- 部署到测试网
- 前端完成钱包连接和调用

价值：

- 补齐最基础的合约和前端交互认知

### 项目 2：链上数据索引服务

做什么：

- 监听某个合约的事件
- 把事件解析后写入数据库
- 提供查询 API
- 前端展示历史记录

价值：

- 这个项目最贴近后端工程师转 Web3 的真实能力
- 能直接体现你在数据链路、异步处理、幂等和服务设计上的优势

### 项目 3：带可观测性的链上服务

做什么：

- 给索引服务加日志、指标、错误重试
- 处理重复事件和链重组带来的异常
- 做基础监控说明

价值：

- 这会把你和普通“教程型项目”拉开差距

## 补充：以太坊协议是什么

如果在申请表、共学报名或求职材料里被问到“以太坊协议是什么”，可以先这样理解：

- 以太坊协议是一套让全球节点共同维护同一份链上状态的规则系统
- 它定义了账户、交易、Gas、区块、状态变化和智能合约执行方式
- 它不仅是一条链，也是一个开放的可编程平台

从结构上看，可以粗略分成两部分：

- 共识层
  - 负责让全网对区块和状态达成一致
- 执行层
  - 负责真正执行交易和智能合约，计算状态变化

从开发者角度看，以太坊协议最重要的意义是：

- 允许任何人部署和调用智能合约
- 让应用运行在公开、可验证的状态机上
- 让资产、规则和业务逻辑可以在同一套开放基础设施上协作

如果要写成一句适合开放问答的回答，可以直接用：

> 我理解的以太坊协议，本质上是一套支持去中心化状态管理与智能合约执行的开放规则系统。它定义了链上交易、账户、Gas 和合约执行方式，也提供了一个无需单一中心即可运行应用的公共计算平台。相比把它仅仅看作一种加密资产，我更关注它作为底层协议和工程基础设施的价值，尤其是智能合约执行、链上数据和可验证计算这些能力。

## 第二部分：先完成最小上手实践

在真正写代码前，先完成一次最小链上体验。

建议练习：

- 创建一个新钱包
- 备份助记词
- 切换到测试网
- 获取测试币
- 发起一笔测试网转账
- 在区块浏览器里查看交易详情

学习目标：

- 知道地址、余额、交易哈希分别是什么
- 能看懂区块浏览器里的基础字段
- 对钱包签名和交易确认有直觉

建议产出：

- 一份《第一次测试网转账记录》
- 记录交易哈希、截图、碰到的问题

## 第三部分：安全是入门必修课

Web3 里最容易踩坑的是安全问题，这部分必须提早学。

重点关注：

- 助记词和私钥不能泄露
- 不要随便点击空投链接
- 不要连接来路不明的钱包网站
- 看清楚签名内容，不要盲签
- 注意假客服、假群、假插件、假官网

学习目标：

- 能识别最常见的钓鱼场景
- 知道什么情况下只是登录，什么情况下是在授权或签名
- 形成自己的基本安全习惯

建议产出：

- 一页《Web3 安全避坑清单》

## 第四部分：协议基础只学最重要的

新手不需要一开始就钻得很深，但至少要知道底层为什么这样设计。

优先理解：

- 比特币解决了什么问题
- 以太坊相比比特币多了什么能力
- 账户模型和 UTXO 的区别
- 智能合约是如何执行的
- Gas 为什么存在

学习目标：

- 能做出比特币和以太坊的基础对比
- 能解释“链上程序”和普通后端程序的差异

建议产出：

- 一篇《比特币 vs 以太坊》对比笔记

- 前端和钱包交互

如果按你的背景做升级版项目，更推荐：

- 合约事件索引服务
- 链上数据查询 API
- 钱包交互 + 后端数据聚合的全栈 demo
- 带监控和重试机制的链上任务服务

学习目标：

- 能写一个简单 Solidity 合约
- 能在本地跑起来并部署到测试网
- 能做一个最小可演示的 dApp

建议产出：

- 一个公开 GitHub 仓库

## 更适合你的 60 天版本

如果你要按“后端转 Web3”的路线执行，下面这个版本更贴近你的情况。

### 第 1 到 10 天

- 搞懂钱包、签名、授权、Gas、交易
- 完成测试网转账
- 写基础概念笔记和安全清单

### 第 11 到 20 天

- 学 Solidity 基础
- 写并部署一个简单合约
- 用最小前端完成调用

### 第 21 到 40 天

- 学事件日志和链上数据读取
- 做一个监听合约事件并入库的小服务
- 设计数据库表和查询接口

### 第 41 到 60 天

- 给项目补 README、架构图、接口说明
- 补日志、错误处理、重试、幂等说明
- 整理成简历项目和 GitHub 展示页

## 推荐使用你给的资料方式

### 1. Web3 Internship Program

用途：

- 看别人是怎么开始的
- 学习如何写公开学习日志
- 参考别人入门前几周都学了什么

建议看法：

- 不要把它当权威教材
- 把它当成“学习路径样例”和“公开记录模板”

### 2. cheng-zhaofeng.md 这类参与者页面

用途：

- 观察一个新人如何记录学习过程
- 参考每周学习节奏
- 学习如何把零散内容整理成可展示材料

建议看法：

- 重点不是照抄内容
- 重点是模仿“记录方式”和“公开节奏”

### 3. web3career.build

用途：

- 了解华语 Web3 社区如何组织人才和项目
- 关注训练营、EPF、求职相关活动
- 找岗位信息、社区入口和同类人

建议看法：

- 它更适合作为社区入口和机会雷达
- 不要只浏览，最好同步整理自己的作品和简介

## 你的最低可交付成果

如果你准备按这条路线走，至少要做出这 5 个东西：

- 一篇 Web3 基础概念笔记
- 一篇安全避坑清单
- 一篇协议对比笔记
- 一个最小可运行 dApp
- 一个公开 GitHub 学习记录页

这 5 个东西做完，你就不再只是“感兴趣”，而是开始具备可展示的入门基础。

## 最后建议

对大陆求职者来说，Web3 更适合作为“技术增量”而不是“投机赛道”。

比较稳妥的路径是：

- 保留原有 Web2 工程能力
- 增加 Web3 技术栈
- 通过开源、项目、公开记录建立可信度
- 面向全球团队寻找机会

对你来说，可以把这句话改成更具体的版本：

- 先把自己定位成一个扎实的后端工程师
- 再补足钱包、合约、链上数据、索引服务这些 Web3 能力
- 最后用一个有工程含量的链上项目完成转型证明

先成为一个懂链上系统的后端工程师，再决定是否深入合约、安全或协议研究，这条路会更稳。
