# 首版范围与验收

目标：把已授权的美团订单转成可追踪的群通知任务，并提供独立运行、管理和 Agent 操作所需的服务。首版截止到模拟发送成功，不发送真实微信消息。

## 交付清单

| 模块 | 本版交付 | 验收方式 |
| --- | --- | --- |
| 订单接入 | 品牌商 `app_id/sig` 回调适配、统一 ERP JSON 入口、模拟订单 | 验签、中文编码、未知门店和无效请求测试 |
| 通知处理 | 门店路由、固定模板、接单及取消通知、去重 | 同一回调重放不重复入队，取消不会恢复过期接单通知 |
| 持久化队列 | SQLite、领取租约、有限重试、异常状态、重启恢复 | 并发领取、租约到期、进程中断和不确定发送测试 |
| 管理服务 | 管理页面、状态和任务 API、路由修改、通知预览 | HTTP 集成验证及页面检查 |
| 发送端协议 | 领取、开始、完成、失败回报；模拟发送 worker | 模拟 worker 通过 HTTP 走完整流程 |
| Agent 配套 | 本地 stdio MCP、操作 Skill、连接配置样例 | MCP 客户端发现工具并实际查询、预览 |
| 运行配套 | CLI、启动说明、容器配置、健康检查、测试 | 全新安装后执行 demo、测试和构建检查 |

## 本版边界

- 使用已有美团开发者账号；不代为申请、绑定或解绑门店。
- 用户尚未确认品牌商还是服务商协议。品牌商验签按官方规则实现；`developerId/sign` 不能套用品牌商算法，识别后明确拒绝，待取得对应文档和脱敏样本后增加适配。
- 真实美团回调、权限及公网 HTTPS 地址需要上线前联调；模拟通过不代表平台已验收。
- 微信端只实现可替换的发送协议和模拟发送，不操作真实微信，不实现 Mac 界面自动化。
- 自动处理由订单接入、队列及运行中的 worker 驱动。MCP 提供管理工具，不声称仅安装 Skill/MCP 就能唤醒 ChatGPT。
- 首版不实现 ChatGPT MCP Events、自定义云端插件发布、多租户账号系统、收费和复杂 AI 决策。
- 密钥从进程环境读取。运行数据库和路由配置存储在 Vault 之外；代码仓库仅保留无密钥的配置样例和虚构订单。

## 完成标准

1. 单命令启动本地演示，页面可导入模拟订单、查看队列和通知预览。
2. 模拟发送与真实发送状态分开，不能把演示结果标成微信已送达。
3. 重复回调、相同订单不同门店、取消早于确认、进程重启等情况下，状态一致。
4. 已开始发送但无法确认结果的任务进入待核对状态，不自动盲目重发。
5. 文档说明如何将已有美团回调接入，以及未来 Mac worker 需实现哪些接口。
