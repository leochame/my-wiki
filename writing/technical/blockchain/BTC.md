
hash 和 签名

- crypto-currency：加密货币
- cryptographic hash function：密码学哈希函数
- collision resistance：抗碰撞性 / 碰撞阻力
- brute-force attack 就是“暴力破解攻击
- sealed envelope在密码学里，它常被用来类比“承诺机制”：  你先把内容“装进密封信封”里交出去，别人暂时看不到；  之后你再打开，证明你之前早就确定了内容，而不是后来改的。
- puzzle friendly 指这种哈希函数很适合拿来设计“需要大量计算才能解开”的题目。  在区块链里，这通常对应“挖矿”那种计算题，也就是不断尝试不同输入，直到结果满足某个条件。
- asymmetric encryption algorithm：非对称加密算法
---

- H(block header) ≤ target：区块头的哈希值 ≤ 目标值
- difficult to solve, but easy to verify：难以求解，但容易验证

意思解释：

H(block header) ≤ target  
表示把“区块头”拿去做哈希计算后，得到的结果必须小于等于某个目标值。  
这就是比特币挖矿里的核心条件之一。

难以求解，但容易验证  
意思是：

- 想找到一个满足条件的区块头很难，只能不断试不同的值
- 但一旦有人找到答案，别人检查一下哈希结果是不是满足条件就很容易

## 2. BTC 的数据结构

哈希指针：
不同于普通指针只存储结构体的地址，哈希指针不仅存储地址，还存储该结构体内容的哈希值。这使得我们不仅可以找到结构体，还能验证其内容是否被篡改。


genesiss block 创始块

Tamper-evident log 讲解了比特币如何利用哈希指针将区块连接成链。每个区块的头部包含前一个区块的哈希值。 


Merkle Tree 是一种哈希二叉树。底层是交易数据的哈希值，向上两两分组再次哈希，直到生成唯一的根哈希值（Merkle Root）。

**Merkle Root**：存储在区块头中，用于代表该区块内所有交易的汇总。


- **轻节点请求证明**：轻节点向全节点询问：“我想确认 TX3​ 是否在第 800,000 个区块里？”
    
- **全节点提供路径**：全节点根据 Merkle Tree，给轻节点发回几个哈希值（这些哈希值被称为 **Sibling Hashes**，即路径上每个节点的“兄弟”节点）。
    
    - 例如：为了计算出根哈希，轻节点需要 TX3​ 自己的哈希、它旁边的 TX4​ 的哈希，以及上一层右侧分支的哈希。
        
- **轻节点自行计算**：轻节点拿回这几个哈希值，自己从下往上做哈希运算：
    
    - Hash34​=Hash(Hash(TX3​)+Hash(TX4​))
        
    - 继续往上算，直到得出最终的根哈希。
        
- **对比结果**：轻节点将算出的结果与它本地保存的那个区块头里的 **Merkle Root** 对比。如果一致，说明 TX3​ 确实存在于那个区块中。



区块链是一个大框架，而 **Merkle Tree（梅克尔树）** 是这个框架中用来组织和验证数据的核心组件。

如果把区块链比作一个账本，那么：

- **区块链（Blockchain）**：是**大结构**，它通过“哈希指针”将一个个区块按时间顺序串联起来。
    
- **Merkle Tree**：是区块内部的**小结构**。每一页账（区块）里的成千上万条记录，都是按照 Merkle Tree 的格式排列的。

是的。矿工在内存中维护着待打包的交易池。每增加一笔交易，Merkle Tree 的结构就会变，对应的 **Merkle Root 也会改变**。因为根哈希变了，矿工必须丢弃之前算了一半的 Nonce（随机数），重新开始挖矿。
