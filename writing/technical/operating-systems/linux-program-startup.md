## Linux 程序从命令到运行：fork / execve / ELF / 动态链接 / 调度

本文以 `ls -l` 为例，按时间顺序串起一个程序从“Shell 输入命令”到“CPU 开始执行用户态第一条指令”的关键路径：Shell 解析与 `PATH` 查找、`fork()` 创建子进程、`execve()` 触发内核按 ELF 映射段并准备初始栈（含 `auxv`）、动态链接器完成依赖库加载与重定位、最后由调度器把进程真正跑起来。

假设我们从 Shell 命令开始，收到一个新命令 `ls` 。

### 第1步：Shell 接收并解析命令

Shell（如 `bash`）先读取你输入的命令，并把它拆成“要运行的程序”和“参数”。

1. **读取命令行**：例如 `ls -l`。
2. **拆分程序与参数**：得到程序名 `ls` 与参数 `-l`。
3. **判断如何执行**：如果是 Shell 内建命令就直接在 Shell 内处理；否则当作外部可执行文件，进入后续的查找与加载流程。

### 第2步：在系统中查找程序文件

对于外部程序，Shell 需要在文件系统中定位名为 `ls` 的可执行文件。它通过一个名为 `PATH` 的环境变量来完成此任务，该变量包含一个目录列表（例如 `/usr/bin:/bin`）。

Shell 会按照 `PATH` 中列出的顺序逐个搜索这些目录，直至找到第一个名为 `ls` 且可被执行的文件（例如 `/usr/bin/ls`）。如果遍寻所有目录均未找到，Shell 将报告错误：“command not found”。

### 第3步：创建新进程 (`fork`)

为运行 `ls`，Shell 需创建一个新的“进程”（即一个正在运行的程序实例）。在 Linux 中，创建新进程的经典方法是使用 `fork()` 系统调用。

`fork()` 的作用是创建当前进程（此处为 Shell）的一个副本，该副本被称为“子进程”，而原进程则为“父进程”。

>写时复制 (Copy-on-Write, COW)
>
>为提高效率，`fork()` 并不会立即完整复制父进程的内存。相反，它让子进程与父进程暂时共享内存数据。仅当任一进程尝试修改共享内存时，内核才会为修改方创建一份新的私有内存页。此技术避免了不必要的内存拷贝，因为子进程很快会加载一个全新的程序，不再需要父进程的内存数据。

### 第4步：用 `execve()` 替换进程映像（内核加载新程序）

上一步的 `fork()` 只是创建了一个“能跑起来的子进程”，它的程序内容仍然是 Shell。要让子进程去执行 `ls`，必须把用 `ls` 的可执行文件替换当前进程的地址空间。

子进程会调用 `execve()`，这会触发一次**系统调用**进入内核。若调用失败（例如权限不足、文件不存在、文件不可执行），`execve()` 会返回错误；一旦调用成功，`execve()` **不会返回**：该进程将不再是 Shell 的副本，而是变成 `ls` 程序。

内核要把 `ls` “装载进来”，核心是读懂可执行文件格式。Linux 上最常见的是 **ELF**，其中两类信息对装载最关键：

- **ELF 头**：提供入口地址等基本信息。
- **程序头表（Program Headers）**：描述哪些段需要被映射到内存，以及每段的权限（可读/可写/可执行）等。

随后内核会完成一系列准备工作，使进程具备“从入口开始跑”的条件：

1. **切换到内核模式**：CPU 从用户态切换到更高权限的内核态执行装载逻辑。
2. **清理旧环境**：丢弃子进程从 Shell 继承来的旧内存布局。
3. **建立新地址空间并映射段**：依据 Program Headers，把 `ls` 的代码段/数据段等映射到进程虚拟地址空间，并设置对应的页权限。
4. **准备初始栈与启动参数**：在用户栈顶放入命令行参数、环境变量，以及辅助向量（`auxv`）。`auxv` 会携带入口地址、程序头表位置等关键信息，供运行时启动逻辑使用。

到这里，内核已经把“能运行的新进程现场”搭好了；接下来是否能立刻跳到 `ls` 的入口，还取决于它是不是动态链接的程序。

### 第5步：动态链接器的工作

第4步里，内核已经把可执行文件的代码/数据映射进进程地址空间，也准备好了初始栈、参数和环境变量等启动信息。但对多数现代程序来说，这还不够：程序往往依赖共享库（`.so`），可执行文件里只记录了“依赖哪些库、要用哪些外部函数/变量”，这些引用在此刻还没有对应到真实的内存地址上。

因此在真正进入程序入口之前，需要先由**动态链接器**在用户态把“依赖关系”和“地址绑定”这件事做完，程序才能正确运行。它主要完成三类工作：

1. **加载依赖库**：读取可执行文件的依赖列表，把需要的共享库加载/映射到当前进程的地址空间。

2. **解析符号并做重定位**：把程序里对外部函数、全局变量的引用，绑定到某个共享库中的具体实现，并把相关位置更新为正确地址，确保后续调用/访问能跳到对的地方。

3. **执行初始化并交还控制权**：按顺序运行主程序与各共享库的初始化代码，然后把 CPU 控制权交给程序入口（例如 `_start`），程序才会继续自己的启动流程并最终进入 `main`。

### 第6步：调度与最终执行
至此，一个完整的、可运行的 `ls` 进程已在内存中准备就绪。

1. **进入就绪队列**：内核将这个新创建的进程标记为 `TASK_RUNNING`（运行中或可运行）状态，并将其放入名为“运行队列” (`runqueue`) 的等待列表中。

2. **调度器选择**：Linux 的**完全公平调度器 (CFS)** 会持续监控运行队列。CFS 的核心思想是公平，它会追踪每个进程的“虚拟运行时间” (`vruntime`)。该值越小，代表进程等待 CPU 的时间越长，也就越有资格被运行。调度器总是选择队列中 `vruntime` 最小的进程。

3. **切换到用户模式并执行**：当调度器决定运行 `ls` 进程时，内核完成上下文切换并返回用户态开始执行，同时将 CPU 的指令指针设置为程序入口地址 (`_start`)，并将栈指针指向准备好的用户栈。

随着这条指令的执行，CPU 正式开始执行 `ls` 程序的第一条机器码。程序运行，读取目录内容，将其格式化后输出到屏幕上，然后退出。整个过程至此完成。
