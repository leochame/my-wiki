## 1. libc

libc 的本质是在底层系统调用（ABI 层级）之上封装的一层抽象。

操作系统仅提供必要的机制（如内存映射、进程创建），而 libc 则负责实现具体的策略（如内存分配算法、格式化输出）。libc 为程序提供了一系列标准化的基础工具：

| 组件 | 说明 |
|------|------|
| 启动例程（Startup） | `_start` 函数作为可执行文件的入口，负责初始化进程环境，解析 `argc`、`argv` 和环境变量（`envp`），最终调用 `main` 函数。 |
| 标准 I/O | `printf`、`scanf` 等函数，其底层通过 `read` 和 `write` 系统调用实现。 |
| 内存管理 | 管理 `malloc` 与 `free` 的用户态内存池。 |

### 1.1 程序启动

在程序执行 `main` 函数之前，libc 需要先完成初始化工作。这主要包括解析操作系统的初始状态，正确获取命令行参数（`argc` 和 `argv`），以及设置程序的环境变量。

一个合法的 C 程序并非从 `main` 开始，而是从 `_start` 开始。在没有标准库的环境下，程序必须自行定义 `_start`。当内核通过 `execve` 启动一个进程时，它并不会调用 `main`，而是直接将控制权交给 `_start`。

此时机器处于一个极其原始的状态。内核会在进程的栈中（通过 RSP 寄存器指向）预先布置好初始进程栈（Initial Process Stack）。这个栈中存放了 `argc`（参数个数）、`argv`（参数指针数组）和 `envp`（环境变量指针数组）的原始数据。`_start` 的第一项工作，就是从这个原始栈中解析出这些信息，然后调用 `main`。

## 2. 可执行文件机制

可执行文件本质上是存储在磁盘上的一个特定数据结构。它向操作系统描述了一个进程运行前的初始状态——包括代码放在哪里、数据放在哪里、第一条指令从哪里开始执行。

目前最通用的标准格式是 ELF（Executable and Linkable Format）。为了节省存储空间，ELF 文件设计得极其紧凑，内部使用大量的偏移量（offset）来定位信息。ELF 文件的核心结构包括：

| 结构 | 说明 |
|------|------|
| 文件头（ELF Header） | 记录文件的整体元信息，如目标架构、入口地址、程序头表的位置等。 |
| 程序头表（Program Headers） | ELF 文件中最关键的部分，包含一系列段描述，其中最核心的是 `PT_LOAD` 类型的段。每个 `PT_LOAD` 段明确指出文件中的哪些字节需要被搬运到内存的哪个具体位置，以及该内存区域应当具备的权限（读、写、执行）。 |
| 段（Sections） | 文件内部划分的不同区域，例如存放代码的 `.text` 段、存放已初始化数据的 `.data` 段，以及存放未初始化数据的 `.bss` 段。 |


### 2.1 可执行文件的生成：静态链接

静态链接发生在构建阶段，由链接器（`ld`）完成，产出最终的可执行文件。编译产生的多个目标文件（`.o`）各自独立、互不依赖，需要经过链接才能合并为一个整体。静态链接的过程分为三步：

1. 段合并。 链接器把所有目标文件中同类型的区块（比如所有 `.text` 代码段、所有 `.data` 数据段）提取出来，按顺序拼接到一起，形成一个平坦的线性地址空间。这一步完成后，所有指令和变量在最终程序里的内存位置就固定了。

2. 符号解析。 在独立编译阶段，文件之间的函数调用或变量引用通常只有一个占位标记。符号解析就是去全局范围内查找每个模块的导出（Export）和导入（Import）记录，把之前未知的调用需求与刚刚确定好的真实目标地址精准匹配起来。

3. 重定位。 匹配成功后，链接器回头修改当初留空的机器指令。它会通过特定的计算表达式（例如 `目标地址 - 当前指令地址 - 4字节`）算出 CPU 执行跳转所需的准确相对偏移量，并把这个数值直接硬编码填回原来的指令中。

### 2.2 可执行文件的运行：加载

可执行文件生成后，它仅仅是磁盘上的一个静态数据块。加载发生在运行阶段——当用户在 shell 中输入程序名或调用 `execve` 时，操作系统负责把这个文件搬进内存，并为它搭建好运行状态。

操作系统首先读取可执行文件的程序头表，根据每个 `PT_LOAD` 段的描述，使用 `mmap` 将文件中的字节序列映射到进程的地址空间中，并赋予相应的读、写或执行权限。

接着，操作系统在内存中为进程构建初始栈（Initial Stack），将命令行参数和环境变量放置在栈的特定位置。这正是前面 libc 启动例程中提到的、`_start` 需要去解析的那个栈。

一切准备就绪后，操作系统将 CPU 的程序计数器（PC 指针）指向代码的入口地址。此时，程序正式作为进程开始执行第一条机器指令。
