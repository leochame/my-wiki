
## 1. HTTP 的升级之路


1. . HTTP/1.0，短连接
2. HTTP/1.1，持久化连接，虽然连接复用了，但请求必须“排队”。如果第一个请求处理得很慢，后面的请求就算处理完了也得等着，导致带宽空闲。
3. HTTP/2.0，
	- 通信双方维护一张索引表，重复的 Header（如 User-Agent）不再重复发送，极大减小了数据量
	- 服务器预测你可能需要的资源（如 HTML 里的 JS/CSS），主动推给浏览器。
	- 并发传输，这是最大的突破。它将请求分成更小的“帧”，在同一个连接上交错发送。这意味着你可以同时请求 100 张图片，谁先准备好谁就先传，不再需要排队。
	- ![[http-and-https-assets/Pasted image 20260317181858.png]]
4. HTTP/3.0，
	- 抛弃 TCP，改用 UDP
	- QUIC 中，不同流（Stream）之间是独立的。一个流丢包了，只会影响自己，其他流照样跑，这才是真正的多路复用。
	- TCP 依靠 IP 和端口识别连接，切换 Wi-Fi 到 4G 时连接会断断续续。QUIC 使用“连接 ID”，只要 ID 不变，网络怎么切换都能无缝重连。
