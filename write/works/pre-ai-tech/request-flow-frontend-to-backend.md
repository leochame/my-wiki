# 一次请求从前端到后端的完整访问链路



## 从 操作系统内部看，发生了什么

发送路径
1. **应用层到内核的传递**  
	- 应用程序通过 socket 接口发送数据时，系统调用会到内核态中的 socket 层，内核申请一个内核态的 `sk_buff `内存，将用户待发送的数据拷贝到 `sk_buff`，并将其加入到发送缓冲区。
2. 协议栈处理与 DMA 传输  
	- 内核协议栈处理 ﻿`sk_buff`﻿，添加必要的协议头（如 IP、TCP/UDP、MAC），然后将其放入发送环形缓冲区（ TX ring buffer ）。  
	- `sk_buff` 是一个数据结构，往上传或者往下传所做的就是一步步填充或者缩减 `sk_buff`的 data 指针。 网络协议栈从 Socket 发送后缓冲区去除﻿ `sk_buff` ﻿，并按照 TCP/IP 协议从上至下逐层处理。  
	但是如果是 TCP 连接就需要拷贝一份 `sk_buff`,以此支持丢失重传。  
3. 发送完成与资源释放
	- 当填充完成 IP、MAC 头部等一系列工作后，会触发软中断告诉网卡驱动程序，有新的网络包进行发送，驱动程序读取 `sk_buff`，将这个`sk_buff`挂到 RingBuffer，紧接着将 `sk_buff`  数据映射到网卡可以访问的内存DMA区域。  
	- 数据发送完成后，网卡可能触发中断，通知内核释放已发送数据的资源，准备处理新的发送请求。
接受路径
4. DMA 进行处理
	- 当网络数据包到达网卡（NIC）时，网卡通过 DMA（直接内存访问）将数据写入内核预先分配的接收环形缓冲区（RX ring buffer）。  RX ring buffer 是一个固定大小的循环队列，包含指向内存区域的描述符，用于存储接收到的数据。
5. 中断与 NAPI 机制
	- 为避免高频率中断带来的性能损耗，Linux 引入了 NAPI（New API）机制。这个机制是唤醒数据接收服务程序，使用poll方法轮询。
	- 在 NAPI 模式下，网卡接收到数据后会触发一次硬件中断，通过中断告诉操作系统网络包到达。
	- 内核的中断处理函数随后禁用进一步的接收中断，并调度软中断（SoftIRQ）来处理数据。
	- 软中断由专门的内核线程 ﻿ksoftirqd﻿ 处理，通过调用驱动程序注册的 ﻿poll﻿ 方法，从 RX ring buffer 中提取数据。
6. `sk_buff` 与协议栈处理
	- 提取的数据封装为 `﻿sk_buff﻿`结构，供内核网络协议栈进一步处理。协议栈根据数据包的类型（如 IP、TCP、UDP）进行相应的处理，并将数据放入对应 socket 的接收缓冲区，最终由应用程序读取。
	在网络协议栈中进行的具体操作包括：  
	- 取出IP包，判断网络包下一步是交给上层还是转发出去。
	- 如果交给上层用于查看是 UDP 还是 TCP ，去掉 IP 头发给传输层
	- 传输层去除 TCP 或 UDP 根据四元组找到对应的 Socket，然后放到对应的 socket 缓冲区，最后应用程序将数据拷贝到应用层
