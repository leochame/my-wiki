## 架构总览

本系统参考 **ChatGPT 最新记忆机制（Memory & Chat History）**，构建了一个**多层级、自动化管理且用户高度可控**的记忆架构。系统通过将会话状态拆分为短期上下文、显式记忆与隐式画像，实现个性化的对话体验，同时通过“Top of mind”相关性算法防止上下文窗口溢出，并具备动态的偏好偏移更新能力。

## 模块一：系统提示词分层架构 (Tiered System Prompt Context)

**职责**：将不同生命周期和类型的记忆数据结构化，并按类别注入到大模型的 System Prompt 中。参考 ChatGPT 的内部实现，分为以下六个核心区块：

1. User Interaction Metadata ：包含客户端环境（设备类型、明暗主题等）、意图标签（`intent_tags`，如 translation、summary）等。提供基础物理与意图环境，辅助大模型调整基础回复策略。
        
2. Assistant Response Preferences： 系统级或用户全局设定的回复风格（例如“以项目符号输出”、“保持简短”），通常带有 `Confidence: high` 标签。
        
3. Recent Conversation ContentL  维持最近约 40 次 交互的滑动窗口。包含：时间戳、纯历史用户输入消息（以 `||||` 分隔），现在的 input。
        
4. Model Set Context 用户明确要求记住的“核心事实”（如“记住我是素食主义者”）。具有最高优先级，这个每次变为 Model Set Context  时候需要User 进行确认。
        
5. Notable Past Conversation Topics Highlights ： 系统从长期对话中提炼出的用户深度特征与偏好（例如经常讨论的技术栈、常用的旅行预订习惯等）。
        
6. Helpful User Insights ： 更加碎片化的背景知识补充，用于丰富用户立体画像。
        

## 模块二：记忆生成与提取引擎 (Memory Extraction Engine)

**职责**：负责从日常对话中提取有价值的记忆节点，分为显式和隐式两条链路。

1. **显式记忆提取 (Saved Memories)**
    
    - **触发逻辑**：当识别到用户指令中包含明确的记忆意图（如“记住……”、“我的名字是……”）时，触发记忆写入。
        
    - **处理方式**：大模型自动将其转化为简洁的事实陈述，并存入 `Model Set Context` 存储区。
        
2. **隐式画像提取 (Reference Chat History)**
    
    - **触发逻辑**：后台异步（例如夜间 ChatGPT Pulse 机制）或在对话周期结束时触发。
        
    - **处理方式**：扫描历史对话，挖掘高频话题、兴趣偏好与潜在习惯，归纳整理后存入 `Notable Highlights` 和 `User Insights`。
        

## 模块三：自动记忆管理与动态更新 (Automatic Memory Management)

**职责**：解决“记忆满载 (Memory Full)”、Token 溢出问题，并动态适应用户的**偏好偏移与习惯改变**。

1. **记忆结构与 Schema设计** 使用结构化的 JSON/KV 存储记忆库，遵循极简设计，仅保留核心内容与防膨胀算法所需的必要字段：
    
    ```
    {
      "id": "mem_001",
      "content": "用户是素食主义者",
      "hit_count": 12,
      "last_accessed": "2026-03-02"
    }
    ```
    
2. **Top of Mind 算法 (动态相关性排序)**
    
    - **淘汰与降级**：系统综合考量记忆的 **“近期活跃度 (Recency)”** 和 **“讨论频率 (Frequency)”**。
        
    - **前后台置换**：高权重的记忆被标记为 `is_top_of_mind: true`，会被优先提取并拼接到 System Prompt 中；低权重的“次要细节”则被置灰（退居后台存储），不再占用实时 Token，直到相关话题再次被触发。
        
3. **偏好偏移与冲突更新 (Preference Shift & Override)** 针对用户口味、习惯等随时间发生的变化，系统提供以下更新机制：
    
    - **显式覆写 (Explicit Override)**：当识别到用户明确表达与已有记忆冲突的新偏好时（如：“我现在的口味变清淡了，不再吃辣”）。提取引擎会检索相关的旧记忆 `id`，**直接覆写**其 `content`，并刷新 `last_accessed`时间戳。
        
    - **隐式衰减 (Implicit Decay)**：当用户未显式声明，但行为发生自然偏移（如：渐渐开始点肉食菜单）。此时，旧的隐式画像（“爱吃素”）因为长期不再被话题触发，其 `last_accessed` 会老化，在 Top of Mind 算法中权重自然下降并退居后台；同时，系统通过扫描新对话，提炼出新的偏好特征并赋予高频权重，迅速接管 System Prompt 的前台记忆。
        

## 模块四：用户控制面板与隐私 (User Control & Privacy)

**职责**：将记忆的控制权完全交还给用户，确保透明度与隐私安全。

1. **透明的记忆管理界面 (Manage Memories)**
    
    - 用户可通过图形化界面或自然语言（“你记得我什么？”）直接查看系统存储的所有显式和隐式记忆。
        
    - 提供细粒度的控制：用户可以手动**编辑**、**优先排序**、或**删除**某条特定记忆。
        
2. **多级别遗忘机制 (Forgetting Mechanism)**
    
    - **指令遗忘**：用户要求“忘记某事”时，系统将其从记忆库移除，但保留原始聊天记录（原始对话的上下文清除需 30 天周期）。
        
    - **全局控制**：支持一键关闭“参考保存的记忆”或“参考聊天记录”，关闭后不再生成新记忆也不再调用旧记忆。
        
3. **临时对话模式 (Temporary Chat)**
    
    - 提供“无痕模式”，在此模式下进行的对话绝对不会读取已有记忆，也不会生成任何新的交互元数据或历史上下文。
        
4. **敏感信息拦截**
    
    - 系统内置安全过滤，被动拒绝主动记忆诸如健康细节、密码等高度敏感信息，除非用户在明确知情下强制要求保存。
